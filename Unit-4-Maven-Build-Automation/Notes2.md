
# 1. Introduction to Maven Plugins

A Maven plugin is a collection of goals that perform specific tasks during the Maven build lifecycle.

Examples of tasks performed by plugins:

* Compiling source code
* Running unit tests
* Packaging applications
* Creating executable JAR files
* Deploying artifacts

Plugins make Maven highly modular and extensible.

---

# 2. Why Maven Plugins Are Important

Without plugins, Maven would only provide lifecycle definitions without performing any actual work.

Plugins are important because they:

* Automate repetitive tasks
* Improve development speed
* Standardize project builds
* Reduce manual configuration
* Support CI/CD pipelines

Maven automatically executes plugins associated with lifecycle phases.

Example:

```id="plug1"
compile phase → Compiler Plugin
test phase → Surefire Plugin
package phase → JAR Plugin
```

---

# 3. Maven Plugin Structure

Plugins are usually configured inside the `pom.xml` file.

Basic structure:

```xml id="plug2"
<build>
    <plugins>

        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.11.0</version>
        </plugin>

    </plugins>
</build>
```

---

## Explanation

### groupId

Identifies plugin organization.

---

### artifactId

Represents plugin name.

---

### version

Specifies plugin version.

---

# 4. Maven Compiler Plugin

## 4.1 Introduction

The Maven Compiler Plugin is responsible for compiling Java source code into bytecode (`.class` files).

It is automatically associated with the `compile` phase of Maven lifecycle.

Without this plugin, Java source files cannot be compiled.

---

## 4.2 Working of Compiler Plugin

The plugin:

* Reads Java source files
* Compiles them using JDK compiler
* Stores compiled files inside:

```id="plug3"
target/classes
```

---

## 4.3 Example Configuration

```xml id="plug4"
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>3.11.0</version>

    <configuration>
        <source>17</source>
        <target>17</target>
    </configuration>
</plugin>
```

---

## Explanation

### source

Defines Java source version.

---

### target

Defines generated bytecode version.

Example:

```id="plug5"
source = 17
target = 17
```

Means project uses Java 17.

---

## 4.4 Compiler Plugin Command

```bash id="plug6"
mvn compile
```

This command:

* Executes compile phase
* Runs compiler plugin automatically

---

## 4.5 Advantages of Compiler Plugin

* Automatic compilation
* Java version management
* Standardized builds
* Better portability

---

# 5. Maven Surefire Plugin

## 5.1 Introduction

The Maven Surefire Plugin is used for executing unit tests during the `test` phase.

It is one of the most commonly used plugins in Maven projects.

The plugin supports testing frameworks such as:

* JUnit
* TestNG

---

## 5.2 Purpose of Surefire Plugin

The plugin automatically:

* Detects test classes
* Executes tests
* Generates test reports

This supports continuous testing in DevOps pipelines.

---

## 5.3 Example Configuration

```xml id="plug7"
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-surefire-plugin</artifactId>
    <version>3.2.5</version>
</plugin>
```

---

## 5.4 Running Tests

```bash id="plug8"
mvn test
```

The command:

* Executes test phase
* Runs Surefire plugin
* Executes all unit tests

---

## 5.5 Example Test Class

```java id="plug9"
import org.junit.Test;

public class DemoTest {

    @Test
    public void testMethod() {
        System.out.println("Test Executed");
    }
}
```

---

## 5.6 Test Reports

Surefire generates reports inside:

```id="plug10"
target/surefire-reports
```

Reports include:

* Passed tests
* Failed tests
* Error details

---

## 5.7 Advantages of Surefire Plugin

* Automated testing
* Early bug detection
* CI/CD integration
* Detailed reports

---

# 6. Maven Shade Plugin

## 6.1 Introduction

The Maven Shade Plugin is used to create an executable JAR file called an Uber JAR or Fat JAR.

An Uber JAR contains:

* Application classes
* Dependencies
* Required libraries

inside a single JAR file.

---

## 6.2 Why Shade Plugin Is Needed

Normally, Java applications require multiple external JAR files.

Example:

```id="plug11"
app.jar + dependency1.jar + dependency2.jar
```

Managing multiple files becomes difficult.

Shade Plugin combines everything into:

```id="plug12"
app-fat.jar
```

This simplifies deployment.

---

## 6.3 Example Configuration

```xml id="plug13"
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-shade-plugin</artifactId>
    <version>3.5.0</version>

    <executions>
        <execution>
            <phase>package</phase>

            <goals>
                <goal>shade</goal>
            </goals>

        </execution>
    </executions>
</plugin>
```

---

## 6.4 Working of Shade Plugin

During package phase:

1. Maven compiles project
2. Dependencies are collected
3. All files merged into single executable JAR

---

## 6.5 Build Command

```bash id="plug14"
mvn package
```

Generated JAR stored inside:

```id="plug15"
target/
```

---

## 6.6 Advantages of Shade Plugin

* Single executable file
* Easy deployment
* Better portability
* Useful for microservices

# 7. Maven Wrapper (mvnw)

## 7.1 Introduction

Maven Wrapper (`mvnw`) allows projects to use Maven without requiring Maven to be installed globally on the system.

The wrapper automatically downloads the correct Maven version required by the project.

---

## 7.2 Why Maven Wrapper Is Important

Different systems may have different Maven versions.

This causes:

* Build inconsistencies
* Compatibility issues

Maven Wrapper ensures all developers use the same Maven version.

---

## 7.3 Wrapper Files

Maven Wrapper generates:

```id="plug16"
mvnw
mvnw.cmd
.maven/
```

---

## 7.4 Running Project Using Wrapper

Linux/Mac:

```bash id="plug17"
./mvnw clean install
```

Windows:

```bash id="plug18"
mvnw.cmd clean install
```

---

## 7.5 Advantages of Maven Wrapper

* No global Maven installation required
* Consistent Maven version
* Better CI/CD integration
* Easy onboarding for developers

---

# 8. Maven Plugin Execution

Plugins are executed automatically when their associated lifecycle phase runs.

Example:

```id="plug19"
mvn package
```

Automatically executes:

* Compiler Plugin
* Surefire Plugin
* Shade Plugin

depending on project configuration.

---

# 9. Plugin Goals

A goal is a specific task performed by a plugin.

Example:

| Plugin          | Goal    |
| --------------- | ------- |
| Compiler Plugin | compile |
| Surefire Plugin | test    |
| Shade Plugin    | shade   |

Example command:

```bash id="plug20"
mvn compiler:compile
```

Runs compile goal directly.

---

# 10. Plugin Lifecycle Integration

Plugins are bound to Maven lifecycle phases.

Example:

| Lifecycle Phase | Plugin          |
| --------------- | --------------- |
| compile         | Compiler Plugin |
| test            | Surefire Plugin |
| package         | Shade Plugin    |

This integration automates the build process.
